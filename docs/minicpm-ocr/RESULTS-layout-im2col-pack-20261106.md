# PP-DocLayoutV3：卷积展开与激活打包融合候选，2026-11-06

已在 llama.cpp 的 SpacemiT 后端实现可选的 IM2COL→量化打包→矩阵乘法融合候选，并补齐服务器 x86 和 RISC-V QEMU 的打包一致性验证。实际版面图中，95 个量化卷积链满足形状及使用次数条件。K3 计算库和执行器已交叉编译，**尚未部署或执行，不能报告板端提速、完整模型融合质量或 EP 等速**。

本阶段继续此前的源码候选，主要补齐测试和实际图覆盖检查。计算源码固定在前阶段 `20261106-layout-im2col-pack/BUILD-MANIFEST.json`；本阶段保留修正前后的测试、生产量化函数、独立日志及 SHA256。原阶段构建、测试失败与历史模型结果没有覆盖。

## 数据流改变

原路径在目标后端写出完整 FP32 卷积展开矩阵，再读回进行激活量化打包，随后调用已有矩阵内核。新候选每个 worker 只提取四行到局部 scratch，立即调用**同一组生产量化函数**写入原有物理打包缓冲区，全部 worker 同步后继续原有矩阵内核；尾部不足四行仍逐行处理。它没有把权重格式改成 EP INT8，也没有修改矩阵累加顺序。

匹配要求相邻 IM2COL、零偏移 Reshape 和 Q4_0/Q8_0 MulMat，连续 FP32 激活及匹配维度；展开张量和视图不能是可见输出，不能另有消费者。还需满足现有 SpacemiT 权重 trait 和内核条件。诊断量化捕获开启时不融合。未匹配的图保留原路径。

配置为 `OCR_LAYOUT_BACKEND=spacemit`、`OCR_LAYOUT_OFFLOAD_IM2COL=1`、`GGML_SPACEMIT_IM2COL_PACK=1`；最后一项默认关闭。`GGML_SPACEMIT_IM2COL_PACK_TRACE=1` 可单独检查融合计数。开关应在创建会话前设置，性能比较每臂使用新进程/会话，避免复用已缓存的图。trace 诊断与无 trace 测速应分开。

## 检查结果

| 检查 | 结果 | 能证明的范围 |
|---|---:|---|
| x86 可移植提取/标准 Q8 打包 | 6 种几何、1/4/8 线程，共 18 项通过 | 提取、回调边界、保护区；不是 SpacemiT 物理格式 |
| 生产 RVV Q8/HP 打包，QEMU | VLEN 128/256/512/1024，各 33 项，共 132 项通过 | 融合与完整展开参考的打包字节相同；完整 FP32 patch 保持未写入 |
| 真实版面图静态匹配 | 卷积 Q8＋投影 Q8/Q4 两候选，各 95/95 个量化卷积链 | 实际图的形状和使用条件覆盖；不代表硬件已分派 |
| K3 交叉构建 | 7 个 RISC-V 产物与源码清单通过本地哈希复核 | 编译/架构/归档；未执行 IME2、RVV 或 TCM |

测试覆盖 stride、padding、dilation、多 batch、非方形核、尾行、负零、输入保持和输出/scratch 保护区；显式拒绝将可见或共享的展开张量消除。生产量化函数从已固定源码按原样提取，`finalize.py` 重建并逐字节核对提取内容。四种 VLEN 中 256/1024 会进入对应 RVV 分支，其他长度使用现有回退；QEMU 结果不包含 IME2 指令或硬件同步验收。

最初 QEMU 使用的 `rv64` CPU 配置触发非法指令；改为 QEMU `max` 并逐项指定 VLEN 后，程序能执行并暴露另一项测试比较问题。HP 四行格式的共享尺度有保留槽位，生产函数不写其中部分字节；旧测试将参考缓冲区清零，却将候选填成 0x6a，逐字节比较因此误报。现统一两缓冲区的初始值并比较全部字节，没有修改生产量化算法、忽略差异或放宽容差。原失败日志保留在前阶段目录。

## 内存规模与限制

| 实际图静态统计 | 数值 |
|---|---:|
| 95 个链的完整 FP32 展开矩阵累计大小 | 1,697,600,000 B，约 1618.96 MiB |
| 对应展开前输入累计大小 | 580,953,792 B，约 554.04 MiB |
| 最大四行 scratch，每个 worker | 53,248 B，52 KiB |
| 最大 scratch，8 个 worker 合计 | 425,984 B，416 KiB |

新路径避免完整展开矩阵的一次写出和后续量化读回，仍会提取全部数值并读写小块 scratch。表中按节点累计的逻辑大小不是 DDR 流量、峰值内存或节省秒数。原 GGML allocator 仍预留 FP32 patch，**没有因此消除其内存分配**；本阶段新增 scratch 来自既有工作区，没有将它放入 TCM。已有 GEMM 的 TCM 行为也未在本阶段验证。

此前同后端 IM2COL 优化的小图输入复制减少约 88%，与本次融合是不同指标；两者不能相加，也不能写成整页提速 88%。本次没有完整模型融合执行、精度质量验收、真实调度后图的融合计数或板端时间。
