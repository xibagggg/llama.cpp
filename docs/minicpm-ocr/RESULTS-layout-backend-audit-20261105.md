# PP-DocLayoutV3：SpacemiT 后端与矩阵精度审计，2026-11-05

当前版面 GGML 执行器固定创建 CPU 后端；实际最终图中 227 个矩阵乘法全部为 F32×F32→F32，未携带 SpacemiT 重排 trait。链接 SpacemiT 库不等于把这些矩阵交给 IME2。这是当前纯 GGML 硬件路径的明确缺口，尚不能声称与 EP 同等硬件覆盖。

## 证据口径

在构建服务器加载与前阶段相同的预转置 FP32 GGUF，开启已验证图优化、关闭 1×1 卷积实验。检查实际依赖裁剪后的 GGML 图及两个矩阵输入，未调用 graph compute；不读取图中未初始化的激活值。不访问板子，也不产生新的速度或质量结论。

图有 3139 节点，工作区 247.8307 MiB。矩阵左输入经过 view 追溯到权重 context，区分常量矩阵与动态输入。结果保留每个矩阵的 K/M/N、类型、根权重名、形状资格和稠密算术量。

|---|---:|---:|---:|---:|
| 常量卷积权重 | 103 | 162.867200 | 88.96% | 95 |
| 常量二维权重 | 107 | 17.710502 | 9.67% | 101 |

稠密算术量按 `2×K×输出元素数` 计算，只用于划分工作量，不是测得的指令数、硬件利用率或耗时百分比。卷积来源可由原权重 rank=4 及 103 个 IM2COL 对应确认；常量二维权重不能全部笼统命名为原始 ONNX Gemm。

## 为何仅添加调度器还不够

`ggml-spacemit.cpp` 的 supports_op 还会检查缓冲区与具体 trait，不能只看包含 MUL_MAT 的 switch。`ime.cpp` 的矩阵分派接受已有 trait、可重排量化类型或符合条件的 F16 权重；其重排选择没有普通 F32 权重分支。本图的 F32 权重没有 extra trait，所以不能从当前类型直接推导 IME2 覆盖。

另外，IM2COL、直接 depthwise、GridSample、MaxPool、自定义掩码等路径还需要 CPU 回退。混合调度时要核对跨后端复制与生命周期。当前自定义算子记录了输入 storage 指针；将来 scheduler 生成输入副本时，需要使回调读取实际 `out->src` 对应的数据，不能继续盲读原始指针。

## 下一步实现重点

1. 优先处理卷积权重的存储布局及量化接入。103 个卷积矩阵占约 88.96% 的矩阵稠密算术量；仅优化常量二维投影无法覆盖主要算术量。
2. 196 个常量矩阵满足当前审计的 Q4 基本形状条件，涵盖约 92.10% 的矩阵稠密算术量。这只是候选资格：还没有转换、校准或后端实测，不能叫做 92% 硬件覆盖或推导同等提速。剩余矩阵必须保留兼容精度或专门适配。
3. 卷积 GGUF 原权重为四维，最快维通常是 1 或 3；Q4 块长作用于 GGML 最快维。不能直接给原始四维权重套 Q4。需要把计算权重打包为 `[M,K]`，另保留 kw/kh/C 的卷积几何信息，随后验证 im2col、矩阵乘法、偏置与输出布局。
4. 接入 SpacemiT scheduler/缓冲区后，用实际后端日志确认选中的是 IME2 或 RVV，以及 TCM 分块，记录复制/重排成本。F16 可作独立精度候选，但 F16 trait 本身也不等于已经进入 IME2。
5. 量化后需要重做两个完整输入的数值、框、类别、阅读顺序和多边形质量检查；不能要求与 FP32 字节相同，也不能只比较最终文字。板端短测获准后再做同输入 GGML/EP 计时，仍待用户确认。

本轮未修改生产执行器或模型精度，没有启动板端推理、更新飞书、提交或推送。原生 PDF 15 秒、扫描 PDF 30 秒及纯 GGML 追平 EP 仍未验证。
