# CTC 固定矩阵 Q8 与对齐候选，2026-11-06

新增 `scripts/ocr/quantize-ctc-linear.py`，将已预转置的 CTC 固定矩阵补零到 32 对齐并量化为 Q8_0，输出 version-3 图。执行器在矩阵前补零激活，在 bias／后续算子之前裁回输出，保留原字符类别和形状。卷积、动态注意力、归一化与 Softmax 仍为浮点，MiniCPM 文本／视觉 Q4 不变。

CTC 可选 `OCR_CTC_BACKEND=cpu-sched/spacemit`，复用既有权重上传与调度；默认仍为 CPU。RISC-V 构建启用 SpacemiT 支持，SDK 报告实际 CTC 精度，兼容旧库缺元数据的情况。候选没有部署到 K3，没有更换默认模型。

构建服务器 x86、4 线程核 0–3，在同两份 PDF 的 162 个真实裁剪上完成四形状 A/B/B/A，共 648 次正式调用。纯图合计均值为 FP32 53.716 s、Q8 49.724 s，观察到少 7.43%；基线波动明显，W4096 变慢，尚未认定稳定收益。W512 GGUF 文件约少 38.93%，不代表 RSS 或 DDR 流量。

162 个最终解码字符串全部一致，7 个裁剪各变化一个时间步的最高概率类别；最大时间步概率误差 0.665，最大置信度差 0.03295。因此不能称逐值等价或质量损失很小，也没有人工标注准确率结论。重复 Q8 概率、CPU scheduler 的完整输出保持一致。36 次非对齐结构测试、两张版面的四输出回归及 5 项 SDK 兼容性检查通过。

初次合成夹具误将有损块尺度当成精确值，失败日志保留；修正为尺度恰为 1 的结构夹具后通过，真实裁剪另外统计有损误差。CLI／共享库已交叉编译，但没有执行 IME2、RVV、TCM 或板端 SDK。纯 GGML／EP 同输入性能以及完整 PDF 的 15／30 秒目标仍待 K3 验收。
