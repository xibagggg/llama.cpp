# PP-DocLayoutV3：卷积矩阵打包及 Q4 质量验证

2026-11-05 开始，2026-11-06 完成服务器验证。FP32 打包后的表格裁剪、扫描整页四个完整输出均与已接受基线逐字节一致。直接 Q4 候选未接受：扫描页的最终阅读顺序发生变化。本阶段没有 K3 推理，也没有 EP 等速结论。

## 实现与量化含义

将 group=1 的卷积常量权重从 `[M,C,kh,kw]` 打包成 `[M,K]`，其中 K=C×kh×kw；单独保留卷积几何信息供 IM2COL 使用。原地打包仅用于全部消费者都是适配卷积的权重；有其他消费者时保留原权重并建立副本。GGML 使用 IM2COL→MUL_MAT→输出布局恢复→bias；输入输出、候选、掩码与阈值均保留。

FP32 打包 103 个普通卷积；Q4_0 打包其中 K 可被 32 整除的 95 个，其余普通卷积及 27 个 depthwise 保留原路径。原模型约 128.43 MiB，Q4 卷积候选约 45.92 MiB；其余权重仍为原精度，不能称为整模型全 Q4。Q4_0 是分块权重量化；激活、累加、偏置和非线性仍可能使用 Q8 点积输入或 FP32，不等同于所有算子用 INT4。

## 完整输出与最终版面

同一共享 x86 构建服务器、4 线程绑定逻辑核 0–3。使用之前保存的两个真实 SDK 输入，三个模型各重复 2 次；每次检查输入未修改、四个完整输出有限及重复哈希一致。FP32 全量哈希必须保持不变；量化质量另外比较最终区域。测试过程不导入 ONNX Runtime。

DETR 的候选编号可能随量化改变，不能仅把相同 query 位置的张量误差当作实际对象偏差。最终区域按相同类别、Hungarian 最大 IoU 匹配，IoU≥0.5 接受；随后比较框坐标、相对阅读顺序、分数和多边形。参考是 FP32 输出，不是人工真值或 OmniDocBench。
