# PP-DocLayoutV3 GGML：混合调度前的输入副本修复，2026-11-06

已修复自定义算子持有原始输入 storage 指针的问题。后续 GGML 后端调度若把输入替换为副本，算子回调读取实际 `out->src`。服务器上 10 组多线程副本测试通过；表格和扫描页的 FP32、Q4、Q8 三种模型，各重复 2 次，四个完整输出与修复前对应候选逐字节一致。K3 交叉构建完成，未部署或执行。

## 修改及边界

原回调直接读取构图时保存的 `layout_operation.inputs[].storage`。加入 SpacemiT/CPU 调度后，GGML 可能为跨后端输入建立副本，保存在算子实际 src 中；原 storage 未必是本次执行应读的数据，继续使用会产生过期读取。

新回调检查实际 src。未替换时直接执行原逻辑；替换时在当前 worker 的局部元数据中重绑定 storage，再执行算子。共享模型计划保持只读，不在多线程之间修改输入指针。类型、各维形状和存储步幅必须一致；缺失输入、未初始化数据或改变布局的副本明确拒绝。当前不支持把不同存储步幅的副本自动转换成原布局。

这覆盖通用广播、Gather、复制、约简、Resize 等共享自定义回调，也覆盖优化后的连续掩码和分块 Concat。GridSample 原回调本就通过 dst->src 读取，未改动。没有引入 ORT、删除输出、减少掩码或修改版面后处理。

## 验证

10 组测试用与原始 storage 内容不同的运行输入，覆盖 Add 广播、Where、Cast、Concat、含负索引的 Gather，以及优化开关两状态。每组四线程，显式非零偏移、输入保持、输出保护字节、共享计划不可变，并拒绝缺失 src 或不同布局。预期值由独立算式生成。

原有分块 Concat 6 组、Concat→Gather 6 组、卷积几何 6 组、连续掩码 11 组同时通过。首次新增测试误将包含保护区的 backing tensor 当作无保护区的逻辑 tensor，因 storage/shape 检查退出；修正测试的显式逻辑步幅与偏移后全部通过，首次失败日志保留。

完整回归使用之前保存的同一表格/扫描 SDK 输入和模型；4 线程绑定 x86 核 0–3，每状态重复 2 次。全部四输出哈希分别与对应 FP32/Q4/Q8 旧结果一致，输入保持且全部输出有限。Q4/Q8 模型自身量化差异仍按前阶段报告理解；本回归不把量化候选当作 FP32 等价。

## 尚未完成的硬件工作

本阶段仅为混合调度准备，尚未把版面执行器接入 SpacemiT scheduler、IME2 或 TCM；副本测试是可控输入替换，不是实际跨后端调度验证。现有 SpacemiT 缓冲区的 is_host=false，CPU 后端也不会直接接收该类型，因此不能靠共用指针跳过正确的跨后端复制。

下一步需把量化权重放入 SpacemiT 缓冲区，完成实际重排与生命周期管理，构建 SpacemiT/CPU 调度，检查 CPU 回退、复制、分段数和硬件算子分派。单纯链接 SpacemiT 库不等于获得 IME2 性能；当前也未证明 Q4/Q8 版面在 K3 上提速或追平 EP。

运行日志中的 graph 时间仅用于正确性回归，不是 ABBA 性能对照，不报告提速百分比。原生 PDF 15 s、扫描 PDF 30 s 和整个纯 llama/GGML SDK 仍待板端验证。
