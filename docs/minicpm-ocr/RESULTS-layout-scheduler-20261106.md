# PP-DocLayoutV3 GGML：量化权重上传与后端调度接入，2026-11-06

已实现版面执行器的可选 SpacemiT/CPU 调度路径，完成服务器 CPU 调度回归和 K3 交叉编译。两张真实输入、FP32/Q4/Q8 三种模型，在普通 CPU 与单后端 CPU scheduler 下各重复两次，共 24 次完整推理；四个完整输出均与各自前阶段结果逐字节一致。未在 K3 部署或推理，尚未证明 IME2/TCM 执行、跨后端复制正确性或性能提升。

## 当前 SDK 与历史差距

默认完整 SDK 的版面检测、视觉编码及 CTC 仍使用 ONNX/EP，文本使用 Q4 GGUF。项目的 `--llama-only` 路径由本仓库专用 GGML 版面/CTC 执行器和 MiniCPM llama.cpp 组成；并非官方原版 llama-server 已直接支持全部模型。GGUF 是模型容器，速度取决于算子实现、数据布局、硬件分派和调度。

| 历史 K3 测量对象 | ONNX/EP | GGUF/llama.cpp | 可支持的结论 |
|---|---:|---:|---|
| 同一 H336×W588 裁剪的视觉编码 | FP16 1.362 s | Q4 3.244 s | GGUF 耗时约 2.38 倍；精度和线程不同，不能当严格引擎对照 |
| 完整表格任务 | 27.678 s | 29.201 s | 历史端到端结果；不能把全部差值归于视觉编码 |
| PP-DocLayoutV3 同输入版面检测 | 历史 EP 有记录 | 尚无 K3 GGML 同口径实测 | 差距待测；不能用 x86 结果补填 |

本阶段没有新增板端速度数据。历史对照已另行归档，本报告不覆盖旧实验或改变其测试口径。

## 本次实现

`OCR_LAYOUT_BACKEND` 支持 `cpu`（默认）、`cpu-sched`、`spacemit`。普通 CPU 行为保持兼容；非板级构建显式拒绝 SpacemiT 请求，非法名称也拒绝，避免配置失效却误报硬件执行。

选择 SpacemiT 时，将打包的 Q4_0/Q8_0 常量矩阵放入该后端专用权重缓冲区，检查 repack trait，并以完整 tensor 上传，调用既有 SpacemiT 上传/重排实现。非量化权重留在 CPU 缓冲区。上传后释放原始 GGUF 数据副本，保留正确的缓冲区和 metadata 生命周期。

为 IM2COL 几何描述等外部叶子建立 CPU 缓冲区所有权；调度器才能安全识别及复制其数据。将量化权重对应的 MUL_MAT 显式分配给 SpacemiT，其余实际算子留在 CPU；分配时检查支持能力。自定义回调沿用前阶段修复，从实际 src 读取副本，保持共享计划只读。

新增 C API `ocr_layout_info` 与 Python `describe_backend()`，记录模式、计算次数、已分配矩阵/CPU 节点、量化权重数量、权重/计算缓冲区字节及 graph splits。这里的分配计数不是 IME2 指令执行计数，`hardware_execution_validated` 仍明确为 false。Python 包装器检查请求的后端是否生效，并在会话销毁后拒绝访问。

这些改动针对 EP 的核心做法：一次性权重重排、硬件矩阵分派、显式缓冲区所有权与图调度。本轮尚未新增卷积+bias+激活融合，不能把已有 EP 或视觉编码优化算成本轮收益。

## 验证结果

服务器使用同一张表格裁剪和扫描整页的已保存 SDK 输入，4 线程绑定 x86 核 0–3，保留 logits、pred_boxes、order_logits、out_masks 全部输出，没有删除掩码或减少候选。FP32/Q4/Q8 各与自身前阶段模型结果比较，不要求量化模型与 FP32 相等。

| 模式 | 模型精度 | 输入×重复 | 完整四输出 | 计算分段 | 加速矩阵实测 |
|---|---|---:|---|---:|---|
| CPU | FP32 / Q4 / Q8 | 各 2×2 | 各自原结果逐字节一致 | 不适用 | 0 |
| CPU scheduler | FP32 / Q4 / Q8 | 各 2×2 | 各自原结果逐字节一致 | 1 | 0 |
| SpacemiT + CPU | Q4 / Q8 卷积候选 | 尚未执行 | 待 K3 核验 | 待测 | 待核验 |

CPU scheduler 中实际分配 1296 个计算节点，计算缓冲区 259869312 B；FP32/Q4/Q8 的 CPU 权重缓冲区分别为 134284704 / 47768384 / 60352576 B。这是 CPU 分配记录，不是 K3 RSS 或 TCM 用量。

另有分块 Concat 6 组、Concat→Gather 6 组、卷积矩阵几何 6 组、连续掩码 11 组、运行输入副本 10 组测试通过，共 39 组。回归检查输入保持、重复输出稳定、输出有限、非法/不可用后端拒绝、小诊断缓冲区保护及销毁后的 API 拒绝；运行过程未导入 ONNX Runtime。

服务器日志保留运行时间，仅用于正确性回归；未做 ABBA 性能对照，不能据此报告提速或硬件差距。CPU 单后端调度也没有跨后端复制，前阶段的可控副本测试与本阶段 CPU scheduler 回归均不能代替真实 SpacemiT/CPU 混合执行验证。

## 剩余工作与验收

1. 板端短测确认后，先验证小型、限时、单进程的 Q8 版面任务，核对实际 SpacemiT/RVV/IME2 路径、输入输出稳定性、CPU 回退、复制和分段，再决定是否扩大测试。
2. 与 EP 采用同输入、同前后处理和明确线程/精度口径比较，分开记录模型/会话创建、重排、纯图计算、复制同步及端到端耗时。不能仅比较模型文件大小或量化位数。
3. 若跨后端复制和 IM2COL 占主要时间，优先移植分块卷积、激活量化复用及 bias/激活融合，减少 CPU↔SpacemiT 边界；TCM 分块需按实际矩阵形状和可用容量核验。
4. 保留框、类别、阅读顺序和掩码质量对照。Q8 卷积候选此前扫描页平均框 IoU 为 0.998342、最大坐标差 1 px；它仍是候选，且不是人工标注准确率。Q4 版面量化与文本/视觉 Q4 是不同组件选择，不能混为一谈。

目前尚未证明全 llama/GGML 追平 EP，也未验证原生 PDF 15 s、扫描 PDF 30 s 目标。K3 保持只读，恢复推理的确认仍待回复；未更新飞书、提交或推送。
