# 2026-11-04：K4304视觉down Q4化与注意力分段优化

实现了适配K4304的Q4路径：权重与激活补零到K4352，复用SpacemiT原生K256 Q4_0／IME2内核。三例正式ABBA中视觉耗时减少23.96%–24.43%，HTTP总耗时减少13.25%–17.78%。文本模型与文本计算配置未变。

这次是新的有损权重量化：10例中9例文字和完整token完全相同；英文整页少一个原图存在的末尾圆点。保留原模型，v50作为实验候选，未替换常驻服务。

## 具体改了什么

1. 原down权重每层4304×1152：4304不能被256整除，且不满足Q4_0的32分组，过去保留F16。
2. 转换器将27层down每行补48个零至4352，再通过官方ggml_quantize_chunk生成标准Q4_0；核验反量化补零全零、其他张量逐字节SHA256相同。没有把4304简单截断。
3. clip图仅对MiniCPM-OCR、n_ff=4304、实际down K4352增加适配，在GELU之后补48个零，bias不变，输出仍1152。必须设置MTMD_OCR_PADDED_DOWN=1；原GGUF继续走旧图。
4. 复用既有IME2 K256计算、N尾部及TCM分块。权重Q4，激活动态Q8，累积FP32；归一化、softmax、文本Q6_K输出等保持其精度，不能称全图INT4。

mmproj文件从465,237,824 bytes（443.69 MiB）降至273,637,408 bytes（260.96 MiB），减少41.18%。正式三例请求后RSS平均减少约180–184 MiB。F16补零控制曾验证输出一致，但它绕开原K4304专用优化，因此其速度未用作正式基线。

独立真实第0层down：N=7/65/988/1008/1057，每形状3次；输出有限且重复逐位一致、输入未变、补零正确。每形状抽96个输出，与反量化Q4权重×F32激活参考比较，W4A8相对L2为0.00526–0.00887。该误差不是相对原F16，也不是OCR准确率。

## 已实现但未采用的注意力方案

完整attention微基准包含准备、复制和同步；N65/1008、无mask/连续layout/非连续含masked行layout。以下是N1008无mask代表点，单位ms，每状态6次：

| 方案 | 原路径ms | 候选ms | 变化 | 决定 |
|---|---|---|---|---|
| PV四查询全宽向量 | 43.4415 | 44.1511 | 1.63%更慢 | 淘汰 |
| 共享V预转FP32 | 43.4415 | 44.6143 | 2.70%更慢 | 淘汰 |
| IME2 QK＋共享向量化K打包 | 43.5104 | 55.1570 | 26.77%更慢 | 淘汰 |

QK初版每query分块重复标量打包K，N1008曾为128.79ms；v55改为每层共享一次K打包、RVV向量化转换，降到55.16ms，但仍慢于原43.51ms。IME2输入Q/K做2^10缩放，避免F16极小数问题；abs>63或非有限值回退。微基准相对L2≤2.68e-7，max abs≤1.20e-7，非逐位一致。没有把微基准误差当完整模型质量。未给无收益方案追加整页压测或叠加“理论收益”。

## 下一步优先级

1. 以v50为性能候选；先扩大易漏标点、细线表格、密集公式的GT质量集。若标点损失不可接受，评估敏感层保留F16或Q8，逐层校准并分别量化收益；这是精度与速度的取舍。
2. 注意力优先优化PV（约46%）和QK（约33%）：为D72设计更合适的寄存器/TCM块，融合IME2输出重排，减少小矩阵调用与pack/unpack；任何IME2新路径都须把准备、复制和重排计入。FP32 softmax概率直接压F16可能影响极小值，不能未经质量验证替换PV。
3. softmax/重缩放约16%：评估向量exp、max/sum与输出重缩放融合；保持mask/全masked行语义，近似exp需单独质量门槛。
4. 文本预填充与生成约占整页剩余24秒，视觉优化后相对占比上升。再按真实文本算子profile优化Q4矩阵、Q6_K输出及GatedDelta；本轮未更改文本路径。

IME2、RVV和TCM通过ggml-spacemit→spine/spert使用；大模型权重仍主要在DDR，计算中存在TCM分块，不能说所有数据始终直接从DDR计算。ORT SpaceMIT EP 2.0.7为另一运行接口，本次未使用；切换EP/DSpark不是无需适配即可获得的加速。
