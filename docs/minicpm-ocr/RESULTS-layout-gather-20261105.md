# PP-DocLayoutV3 GGML 常量选取与中间物化优化：2026-11-05

本轮消除“沿同一轴拼接多个输入，再用常量标量索引选其中一个”的重复物化，按原图语义直接建立所选输入的视图。四个完整输出与先前已验证 GGML 结果逐字节一致；服务器 GGML 工作区从 576.1719 MiB 降到 247.8307 MiB，减少 56.99%。

交错测试均值 5.580558 → 5.275915 s，耗时少 5.46%，但单次范围明显重叠，不能确认稳定的独立提速幅度。K3 候选已交叉编译归档，未部署、未运行。未更新飞书，没有提交或推送源码。

## 图简化的依据

源模型的四组输出路径均有同轴 Concat → Gather，Gather 的索引来自同一个常量 I64 标量，值为 -1。本轮不硬编码输出名或索引值：在构图时核验轴、标量常量、各输入形状和轴总长度，再把索引定位到对应输入及局部偏移。负索引按 ONNX 语义归一化。

最显著的原中间张量为 `[1,6,300,200,200]`，288,000,000 字节，随后原图只选取其中一份完整的 `[1,300,200,200]` 掩码。优化保留这份原本就返回的完整掩码，并保留类别、框、阅读顺序三个其他输出。

输入可为非连续视图；结果保留 storage、offset 和 stride，去除索引轴。其他消费者仍可引用原 Concat；图依赖只裁剪最终输出不再需要的节点。四组索引的来源、所选张量和形状在 `PLAN-AUDIT.json`，依赖检查显示可达原模型节点 1408 → 1220，188 个只服务于未被选中结果的节点不再执行。不是减少检测候选、截断掩码或修改模型输出。

独立环境开关为 `OCR_LAYOUT_FOLD_CONCAT_GATHER=1`，默认关闭，创建会话前设置。计时中的两个状态均开启前阶段 `OCR_LAYOUT_PACKED_CONCAT=1` 与原生逐元素/复制优化，仅切换本项。

## 后续优先级与当前限制

1. 剩余重点是 227 个 MUL_MAT 与 103 个 IM2COL；需要面向真实 K3 形状做权重准备、卷积布局、后端调度和 IME2/TCM 分块。27 个 depthwise Conv 使用独立直接实现。
2. 大掩码 Where/Cast/Greater 仍有约 1 秒诊断开销，适合连续步进、广播专用循环及合法融合；任何改动都继续检查四个完整输出。
3. 版面和 CTC 当前是项目内新增的 GGML 执行器，共享 llama.cpp 仓库计算引擎，不是未修改 `llama-server` 的直接模型支持。完整 `--llama-only` SDK 已有入口，但 K3 端到端、视觉漂移复验和同输入 EP 速度对照仍未完成。
4. K3 本轮保持只读，所有新推理在 x86 服务器完成。原生 PDF 15 秒／扫描 PDF 30 秒目标本轮未证明。GGUF 是存储格式，提速依赖图和硬件实现，不是改扩展名就等速。
