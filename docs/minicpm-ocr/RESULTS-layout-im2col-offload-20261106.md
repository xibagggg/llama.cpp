# PP-DocLayoutV3 GGML：减少 IM2COL 跨后端搬运，2026-11-06

已在 llama.cpp 的 SpacemiT 后端加入可选的 FP32 二维 IM2COL 路径，将量化卷积前的 patch 展开放到矩阵计算所在缓冲区。服务器小图验证实际输入复制量减少 87.50%–88.19%、分段从 3 减为 2，开关前后输出一致。真实表格和扫描页的 FP32/Q4/Q8 模型也完成 12 次完整推理，四个完整输出均与各自已接受结果逐字节一致。

这些都是服务器正确性和复制机制验证，不是 K3 提速实测。K3 新后端已独立交叉编译并归档，尚未部署或执行；IME2/TCM 行为、整页耗时和与 EP 的差距仍未验证。默认不启用此候选。

## 依据：卷积展开后的矩阵很大

在同一实际版面图的 Q4/Q8 卷积候选中，95 个量化矩阵均读取 IM2COL 输出，覆盖约 82.43% 的矩阵稠密算术量。按每个消费者的逻辑 tensor 大小累计：

| 统计项 | 字节／页 | 约 MiB／页 |
|---|---:|---:|
| 展开后的矩阵输入 | 1697600000 | 1618.96 |
| 展开前的图像／特征输入 | 580953792 | 554.04 |
| 两者差值 | 1116646208 | 1064.92 |
| 量化矩阵输出 | 405280000 | 386.51 |

若先在 CPU 展开、再把展开结果复制给 SpacemiT，将搬运远大于原输入的数据。将展开移到目标缓冲区，可改为复制原输入，再在该缓冲区生成矩阵。

表中是静态、逐消费者估算，不是 DDR 实测流量、峰值内存或速度。真实调度还受 tensor 复用、视图、geometry 常量复制、分段和工作区生命周期影响。约 1.12 GB 的差值不能直接换算成节省秒数或整页提速。

## 代码改动

新增 `ocr-im2col-f32.h`，仅接受已验证的 F32、连续输入/输出、二维正步长/膨胀和非负 padding，检查输入/几何/输出形状。按完整输出 patch 分工，worker 各写不相交区域；连续核宽度通过整段 copy/zero 处理，膨胀核保留逐点取值。不新增量化，不读取卷积核数值，不申请额外 scratch，也没有宣称使用 TCM。

SpacemiT 的能力查询和 common dispatcher 已接入该算子；既有后端在每个算子完成后仍执行全 worker 同步，保留 IM2COL→矩阵计算的数据依赖屏障。未修改文本、视觉编码的量化或内核。

版面调度器增加 `OCR_LAYOUT_OFFLOAD_IM2COL=1` 可选项。只把已经交给 SpacemiT 的量化矩阵上游 IM2COL 一起分配给它，其余算子维持原路径。能力预检查使用调度复制后的存储布局描述；真正的缓冲区仍由 GGML scheduler 创建、复制和管理，没有把专用缓冲区伪装成 CPU host 内存。

只有 `OCR_LAYOUT_BACKEND=spacemit` 且该开关开启时才选择新路径。新增诊断记录分配的 IM2COL 数及静态输入/展开字节；这些仍不是硬件执行或实测复制计数。该配置是待板端验收的候选。

## 真实调度复制的小图验证

测试使用两个互不接受对方缓冲区类型的后端，GGML scheduler 必须建立副本。目标后端是测试设备，数学计算仍在 x86 CPU：测试注入生产版面分配逻辑，量化重排与 SpacemiT API 均未调用。IM2COL 本身执行新内核；卷积矩阵用可精确核验的 FP32 合成权重。因此不能把此测试写成 K3 或量化卷积性能。

| batch | 开关 | 2 次计算输入复制 B | 2 次计算输出复制 B | 分段 | 输出 |
|---:|---|---:|---:|---:|---|
| 1 | 关闭 | 20736 | 18432 | 3 | 独立公式一致 |
| 1 | 开启 | 2592 | 18432 | 2 | 与关闭相同 |
| 2 | 关闭 | 41472 | 36864 | 3 | 独立公式一致 |
| 2 | 开启 | 4896 | 36864 | 2 | 与关闭相同 |

表中记录计算期间实际经过测试设备 buffer API 的字节，排除一次性权重上传；开启时包括 geometry 常量复制。输入复制分别减少 87.50% 和 88.19%；输出复制没有减少，不能把这两个百分比当作整图速度提升。

前一阶段还新增 10 组 Add/Copy/Concat/Gather/ReduceSum 往返测试，各运行 3 次，每次四个交替后端分段，共观察到 60 次真实输入副本替换。它补充先前手工指针替换测试，覆盖共享计划保持、重复新输入、输入保持及缓冲区保护。第一次编译的回调 const 签名错误和集成测试的内部符号链接错误已修正，失败日志保留。

## 新内核完整模型回归

8 种几何、1/4/8 线程，共 24 种核执行组合，同时与 GGML CPU 原实现及独立坐标公式逐字节比较，覆盖 stride、padding、dilation、非方形核、多 batch、负零、输入保持和输出保护区；不支持的 dtype、布局和非法几何显式拒绝。

完整模型使用前阶段已保存的同一表格裁剪和扫描整页输入，x86 4 线程绑核 0–3；FP32/Q4/Q8 各重复 2 次，共 12 次推理。测试在已接受图/存储上仅替换全部 103 个 IM2COL 的 compute 回调，保留所有矩阵、类别、候选、order_logits 和 out_masks，实际调用新内核 1236 次。四个完整输出与各自原结果逐字节一致，输入保持，重复结果稳定且输出全部有限。

该完整回归验证新提取内核在真实图中的结果，仍由 x86 CPU 完成，不包含实际 SpacemiT 重排、跨后端硬件同步或板端质量验收。小图的真实调度测试与完整图回归是两项互补证据，不能合并称为 K3 混合执行通过。

## K3 构建与下一步

本轮使用新目录 `build-layout-im2col-offload-k3` 构建 CPU/SpacemiT/基础库及版面 CLI、共享库和核测试程序，保留 CMakeCache、完整编译命令、源码清单及二进制 SHA256；源码和构建定义包含 IME2，但仅编译成功不代表执行了 IME2。测试设备代码不进入 K3 产物。

板端短测确认后，先做限时小图与 Q8 版面单次验证，检查真实复制、分段、IME2/RVV 分派和特征稳定性，再与 EP 做同输入、同前后处理、明确线程/精度的对照。若实测表明展开仍占主要时间，下一步将展开、Q8 激活打包与矩阵分块合并，减少完整 F32 patch 的写回；再考虑 bias/激活融合和 TCM 分块。保留四个完整输出与最终框、阅读顺序和掩码检查。

当前仍未证明纯 llama/GGML SDK 追平 EP、原生 PDF 15 秒或扫描 PDF 30 秒。板端保持只读；恢复短测的确认仍待回复。未更新飞书、提交或推送。
